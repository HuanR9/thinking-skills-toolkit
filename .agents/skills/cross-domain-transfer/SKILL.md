# 跨领域迁移 / Cross-domain Transfer

## 语言 / Language

默认以用户当前使用的语言回答：中文请求用中文，English requests use English。混合语言或要求双语时，为机制、适配条件和失配风险提供中英对照；案例名称、出处和用户原文不擅自翻译。Match the user's language and preserve case names and sources unless asked to translate.

## 目标 / Goal

从其他领域迁移机制而非表面标签，以拓宽解法空间。Broaden solution space by transferring mechanisms, not superficial labels.

## 流程 / Process

1. 提取底层结构：参与者、激励、反馈回路、瓶颈、约束和失效模式。Extract actors, incentives, feedback, bottleneck, constraint, and failure mode.
2. 用领域中立的语言复述该结构。Restate the structure in domain-neutral language.
3. 选取三个真正遥远、但共享同一机制的领域或历史案例；逐一说明源问题、机制、结构匹配、可迁移部分和可能失配。Select three distant cases and state mechanism, match, transfer, and mismatch.
4. 将最强的三个机制转化为用户情境下的选项。Translate the strongest mechanisms into context-specific options.
5. 推荐一个检验最有希望迁移方案的低成本、可逆实验。Recommend one low-cost, reversible test.

## 证据与边界 / Evidence and boundaries

- 清楚区分已核验历史案例与示意性类比；无法研究时不编造来源细节。Distinguish verified cases from illustration; never fabricate sources.
- 明确失配条件：规模、激励、监管、资源、用户和时间跨度常会使迁移失效。Name mismatch conditions explicitly.
- 价值取决于真实案例证据而非创意时，使用 `$deep-research`。Use `$deep-research` when evidence about real cases is needed.
